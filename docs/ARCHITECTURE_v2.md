# StrategyLab 技术架构 v2

## 核心设计原则

1. **数据本地化** - 预下载常用因子数据，避免实时API调用延迟
2. **分析深度化** - LLM不仅解读数字，更分析市场逻辑和因子有效性
3. **计算高效化** - 本地预计算因子，回测时直接读取

## 数据层设计

### 本地数据存储
```
data/
├── raw/                    # 原始数据
│   ├── prices/            # 日线行情（后复权）
│   ├── fundamentals/      # 财务数据
│   └── macros/            # 宏观数据
├── factors/               # 预计算因子
│   ├── technical/         # 技术指标因子
│   ├── fundamental/       # 基本面因子
│   └── alternative/       # 另类数据因子
└── cache/                 # 回测缓存
```

### 预置因子库

**技术面因子**
- 动量类：MOM(20/60/120日)、RSI、MACD
- 波动类：ATR、波动率、Beta
- 量价类：换手率、量比、Amihud非流动性

**基本面因子**
- 估值类：PE、PB、PS、EV/EBITDA
- 质量类：ROE、ROA、毛利率、资产周转率
- 成长类：营收增速、利润增速

**宏观/市场因子**
- 市场状态：沪深300趋势、波动率指数
- 流动性：Shibor、期限利差
- 情绪：融资余额、北向资金流向

## 分析层设计

### 报告A：数据指标（量化）
保留原有指标，但增加因子暴露分析

### 报告B：逻辑分析（质化）- 重点

**市场本源逻辑分析框架**

1. **因子有效性诊断**
   - 该因子在历史上为什么有效？
   - 当前市场环境是否支持因子继续有效？
   - 因子的经济/行为金融学解释

2. **策略逻辑自洽性**
   - 入场和出场逻辑是否一致？
   - 风控规则是否破坏了收益来源？
   - 是否存在幸存者偏差或前视偏差？

3. **市场环境适配度**
   - 策略在牛市/熊市/震荡市的表现差异
   - 与当前市场风格的匹配程度
   - 同类策略的拥挤度分析

4. **可执行性评估**
   - 换手率是否过高（冲击成本）
   - 持仓集中度风险
   - 极端行情下的流动性风险

## 实现路径

### Phase 1：数据基建（1-2周）
- 搭建数据下载管道（AkShare → 本地SQLite/Parquet）
- 实现因子计算引擎
- 预计算常用因子

### Phase 2：回测引擎（2-3周）
- Backtrader集成本地数据
- 策略解析API
- 回测执行和结果存储

### Phase 3：分析引擎（2周）
- LLM分析框架设计
- 市场逻辑知识库构建
- 报告生成

### Phase 4：前端（2周）
- Playground对话界面
- 结果可视化
- 本地存储

## 技术选型调整

| 组件 | 原方案 | 新方案 | 理由 |
|-----|-------|-------|------|
| 数据存储 | 实时AkShare | 本地SQLite + Parquet | 速度、稳定性 |
| 因子计算 | 回测时计算 | 预计算 + 缓存 | 响应速度 |
| 分析深度 | 通用LLM解读 | 领域知识增强的LLM | 专业度 |
| 部署 | 纯云端 | 本地优先 + 云端可选 | 数据敏感 |

## 数据更新策略

- 日线数据：每日收盘后自动更新
- 财务数据：季报发布后更新
- 因子数据：依赖数据更新后批量重算
